Local stdio is the smallest trust boundary: the MCP client launches the compiled server and
communicates over its standard input and output streams. No network listener is opened.

<InstallMethod method="stdio" />

## Configure a client

<Steps>

1. **Get and build the server.** Clone the project if you do not already have a checkout, then build
   it:

   ```bash
   git clone https://github.com/enthouan/simplelogin-mcp.git
   cd simplelogin-mcp
   corepack enable
   pnpm install --frozen-lockfile
   pnpm build
   ```

2. **Use an absolute entry path.** Point the client at this checkout's `dist/index.js`.

3. **Set the transport and key.** [Create a dedicated key](../simplelogin-api-key/), then pass
   `TRANSPORT=stdio` and `SL_API_KEY` in the client process environment.

4. **Restart the client.** Reopen it so the process configuration is reloaded.

</Steps>

<Aside type="caution" title="Keep the client configuration private">
  `MCP_AUTH_TOKEN` is not needed for stdio because there is no HTTP endpoint. The client config
  still contains `SL_API_KEY`, which grants full account control. Never commit or share it.
</Aside>

The server writes diagnostics to stderr because stdout is reserved for MCP messages.

## Verify through MCP

After the client reports that `simplelogin-mcp` is connected and its tools are discovered, verify a
read-only account call.

<VerifySetup />

Use [Operations](../../guides/operations/) when upgrading or rolling back the source checkout used
by this client configuration.
