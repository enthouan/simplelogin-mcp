Start with the MCP client you already use. For a client and server on the same machine, local stdio
is the smallest trust boundary and does not open a network listener. Docker Compose and direct
Streamable HTTP remain available when you need a persistent service.

## Prerequisites

- A SimpleLogin account with a [dedicated API key](simplelogin-api-key/).
- Git, which the installation commands use to clone the repository.
- Docker with Docker Compose, or Node.js 24.x with Corepack and pnpm 11.5.1.
- An MCP client that supports Streamable HTTP or stdio.

<Aside type="caution" title="Treat the API key like a password">
  `SL_API_KEY` grants full SimpleLogin account control. Create a dedicated key, never commit it, and
  revoke it at SimpleLogin if it leaks.
</Aside>

## Common path

<Steps>

1. **Choose the client.** Prefer its private user-level configuration or secret store.

2. **Choose the trust boundary.** Use stdio for a client-launched local process, direct HTTP for a
   loopback service, or Compose for an operator-managed service.

3. **Set `SL_API_KEY`.** [Create a dedicated key](simplelogin-api-key/), then keep it in an ignored `.env`,
   client secret store, or deployment secret.

4. **Protect HTTP when required.** The startup guard refuses Compose and non-loopback binds without
   `MCP_AUTH_TOKEN` unless the explicit unsafe override is enabled. Supported deployments keep the
   token rather than bypassing the guard.

5. **Verify discovery and one read.** Health is only a process check; approve only the supplied
   `account_get_stats` call to verify the complete MCP and SimpleLogin path without changing the
   account.

</Steps>
