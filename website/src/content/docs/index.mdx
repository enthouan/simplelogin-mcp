## Useful by design

The server focuses on repeatable SimpleLogin workflows that fit an MCP conversation, with bounded
reads and explicit guards around permanent changes.

<ul className="workflow-list not-content">
  <li>
    <article>
      <h3>Create and tune aliases</h3>

    Find an alias, create a random or custom one, update its routing, then explicitly enable or
    disable it.

    `alias_list → alias_create_random → alias_update → alias_set_enabled`
    </article>

  </li>
  <li>
    <article>
      <h3>Investigate recent mail</h3>

    Inspect one alias, then walk bounded activity pages for forwards, replies, blocks, and bounces.

    `alias_get → alias_activity_list`
    </article>

  </li>
  <li>
    <article>
      <h3>Send from an alias</h3>

    Create or reuse a reverse alias for a recipient, and block forwarding before choosing permanent
    deletion.

    `contact_create → contact_set_blocked`
    </article>

  </li>
  <li>
    <article>
      <h3>Maintain account routing</h3>

    Review mailbox verification, inspect custom domains, and review or change supported account-wide
    alias settings.

    `mailbox_list → custom_domain_list → settings_get → settings_update`
    </article>

  </li>
</ul>

## Bring your own account and host

Run locally with stdio, keep HTTP on loopback, or place an authenticated deployment behind
infrastructure you control. The runtime sends requests only to your configured SimpleLogin API.

[Install and run the server](getting-started/) or [review the security model](guides/security/).
